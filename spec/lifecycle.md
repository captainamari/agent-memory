## 收录

先读入口与写作规范，检索现有 ID、别名、标题和正文。重复问题优先补现有文档，独立问题才新建。通过 new_memory 创建 inbox 候选，填写来源、正文、适用条件及关联；候选不会被普通召回使用。

提升前检查有无未解决冲突和未经确认的推断。manage promote 默认预览，--apply 在临时副本更改状态、移动文件、重建索引并校验；失败不接受该变更。shared 文档可通过 --to 指定 global 或 playbooks 目标。

## 更新与冲突

保留 ID 与 created。新增依据后更新 updated，重大结论在正文说明修正对象、日期和原因。并列变体保留各自前提；来源冲突没有证据消解时保留分歧，不能只按最近日期覆盖。

工具不会主动改写正文，agent 或用户编辑后执行 build_index 和 check_memory。直接编辑不属于工具锁保护，修改前查看 Git 状态，完成后审阅差异。规范与验收集不要因失败自动重写。

## 移动、归档与删除

先执行 impact，检查 related、supersedes、正文链接、file 来源及评测提及。ID 链接在移动后保持有效；路径链接不会被盲目改写，断链会拒绝整个暂存变更。

归档移至 archive，保留稳定身份和来源。普通问答不使用历史，明确历史任务才加 --include-archived。活动内容仍依赖待归档文档时先处理依赖；明确 supersedes 的历史引用应保留。

delete 仅接受没有入站引用及评测提及的文档。删除前判断是否应该归档、是否存在外部引用；脚本无法发现仓库之外的依赖。不得为了删除而机械清空正文和回归用例。

移除的文档不留在生成索引中。空分类可以保留说明，也可在确认无用途后移除。共享文件和附件只在确认无其他引用后处理。

## 写入与恢复

CLI 使用排他 .memory.lock；修改在临时副本先通过校验，再逐文件替换，普通 I/O 失败尝试恢复原文件。该机制不是跨文件系统事务，也不阻止绕过工具的编辑器。读取工具遇到锁会拒绝，避免读取工具维护过程中的中间状态。

进程异常结束时先确认没有活动写进程，再比较 Git 差异、恢复未完成文件、删除残留锁，重建索引并全量检查。用户内容修改后以一次 Git 提交保存可恢复快照；本工具不自动提交或推送。
